## Key Discussion Points

### Retrieval Metric
- Metric: For a given corporate action, count of relevant filings extracted / total relevant filings available
- Can be computed via API call to get document counts
- Rationale: Ensures coverage of most important filings at each pipeline step

### Data Sources & Overlap
- **SEC filings**: Primary input pipeline
- **Business Wire API**: Provides pre-extracted data with industry usage history; overlaps with SEC since same underlying source
- Intended use: Historical validation data to check end-database outputs, not as pipeline input

### Validation & Ground Truth
- Manual annotation identified as high-value approach (precedent: prior capstone team used this for image detection)
- LLM role: Compare manual annotations against pipeline outputs to surface differences
- Concern raised: Team's limited business knowledge may affect annotation quality
- Alternative: Build heavy/expensive "gold standard" pipeline for model distillation to evaluate cheaper/faster versions

### Demo with Lauren (SME)
**Purpose**: Pressure-test problem understanding, not technical architecture
**Prepare**:
- Clear problem statement
- Input/output examples (what does one input→output pair look like?)
- Data sources and evaluation method
- Questions on industry standards and scale requirements

**Avoid**: Fine-tuning metrics before validation, assuming architecture feedback from business SME
