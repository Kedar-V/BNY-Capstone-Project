## Problem Statement (Team's Framing)

Corporate action information is:

* **Buried** across SEC filings in large, messy, complex documents
* **Scattered** across footnotes, exhibits, supporting documents (pricing, deadlines, conditions)
* **Evolving** — events change over time via amendments (offer price, expiration dates, conditions)
* **Context-dependent** — values need linkage to specific events, fields, and source filings

**Scope:** Mergers, tender offers, exchange offers, rights issues, conversions (demo focused on mergers + tender offers)

***

## Pipeline Architecture (8 Steps)

| Step | Function                                                     |
| ---- | ------------------------------------------------------------ |
| 1    | SEC metadata setup (discovery, indexing)                     |
| 2    | Fetch complete source documents + exhibits from EDGAR        |
| 3    | Normalize (HTML → clean, searchable text)                    |
| 4    | Extract key candidate facts                                  |
| 5    | Construct event representation (preserve evidence + context) |
| 6    | Verify, reason, resolve conflicts                            |
| 7    | Build event chain (track updates/amendments)                 |
| 8    | Downstream alerts + client notification                      |

## Demo Highlights

* **Fetch latest filings:** Pulls from SEC EDGAR, processes via LLMs, stores in database

## Evaluation Framework

### Two-Track Approach

|                  | Offline Validation                                                   | Online Validation                                            |
| ---------------- | -------------------------------------------------------------------- | ------------------------------------------------------------ |
| **Purpose**      | Baseline before deployment                                           | Continuous observability in production                       |
| **Method**       | LLM multi-task extraction + manual checks on 1,000-sample golden set | Stratified sampling + backward LLM search                    |
| **Cost control** | Synthetic data generation                                            | Post-extraction validation (cheaper than full-document pass) |
| **Fallback**     | Compare pipeline vs. LLM performance                                 | Human notification on confidence threshold breach            |

**Key claim:** Achieve GPT-4 level performance at lower cost/latency; improve further with real ground truth data

***

## Critical Feedback from Lauren

### Missing Data: Dates Are Essential

| Field              | Why Critical                                                                 |
| ------------------ | ---------------------------------------------------------------------------- |
| **Record date**    | Determines shareholder eligibility (who holds shares on this date qualifies) |
| **Deadline dates** | For voluntary events — when must shareholders elect?                         |
| **Pay dates**      | When debits/credits occur                                                    |
| **Classification** | Mandatory vs. voluntary — does shareholder have choice?                      |

> *"Key dates drive processing... not just what's happening and why, but what does it mean to them and their shares"*

### Highest-Risk Error: Wrong Deadlines

**Scenario:** Incorrect deadline causes missed election window

* **Financial impact:** BNY liable to make client whole
* **Example:** Client entitled to $1/share, market only offers $0.50 — BNY absorbs $0.50/share loss
* **Root cause:** Operational error from bad date data

> *"9 times out of 10, these corporate actions are offering something favorable versus standard market dealing"*

### Biggest Pain Point: Free Text Standardization

* Current manual process: Read source text, ensure suitable detail level for clients
* **Subjective, time-intensive, inconsistent across events**
* **Opportunity:** AI-generated standardized text for tender offers/mergers with consistent key information

> *"If you could do something where it can be consistent... is there key information always consistent? Could you use an AI agent to help create that text?"*

### Human-in-the-Loop Design Question

Lauren posed for future consideration: *What should the human reviewer actually do?* — suggests incorporating confidence scores to signal review depth needed

***

## Technical Approach Explained

### Hybrid Architecture (LLM + Traditional NLP)

| Component                    | Role                                                                                                |
| ---------------------------- | --------------------------------------------------------------------------------------------------- |
| **Regex + section matching** | Initial document parsing                                                                            |
| **GLiNER (NER model)**       | Extract named entities (acquirer, target, dates, prices) — deterministic, cheaper, no hallucination |
| **LLMs (GPT-4)**             | Generate synthetic training data; validation in production                                          |
| **Structured database**      | Concise representation enables downstream AI agents with reduced hallucination risk                 |

**Core trade-off:** LLMs powerful but expensive/high-latency/opaque; traditional NLP cheaper/faster/explainable when properly trained

***

## Open Questions & Next Steps

* **Immediate:** Add date extraction (record dates, deadlines, pay dates) and mandatory/voluntary classification
* **Medium-term:** Explore AI-generated standardized notification text
* **Design:** Define human-in-the-loop workflow with confidence-score-driven review tiers
* **Follow-up:** Lauren available for future session in \~1 month

***

## Key Decisions

| Decision                                | Rationale                                                           |
| --------------------------------------- | ------------------------------------------------------------------- |
| Prioritize dates in extraction pipeline | Highest operational risk + client impact per expert feedback        |
| Maintain hybrid LLM + NER approach      | Cost, latency, and explainability requirements for production scale |
| Build confidence scoring into UI        | Enables tiered human review (Lauren-endorsed direction)             |
